# 네트워크 & 웹 보안 Q&A 정리
## 1. 재전송 공격 (Replay Attack) 예시
- 정의: 공격자가 유효한 인증 데이터를 가로채 그대로 재사용하는 공격
- 예시: 로그인 패킷 캡처 후 동일 패킷 재전송하여 인증 우회
  - 세션 토큰 탈취 후 해당 토큰으로 API 요청
  - 은행 송금 요청 패킷을 여러 번 재전송
  - 방어: nonce(일회용 숫자), 타임스탬프, 시퀀스 번호 사용

## 2. OAuth는 다이제스트 인증 방식을 사용하나요?
- 아니요, OAuth는 다이제스트 인증을 사용하지 않음
- OAuth 1.0: HMAC-SHA1 서명 기반 (다이제스트와 다름)
- OAuth 2.0: Bearer 토큰 방식, HTTPS 의존
- 다이제스트 인증: HTTP 기본 인증의 대안으로 MD5 해시 사용
둘은 완전히 다른 인증 프레임워크

## 3. 단방향 해시 (One-way Hash)
- 정의: 입력값을 고정 길이 출력으로 변환하되, 역산이 불가능한 함수
- 특징:
  같은 입력 → 항상 같은 출력
  출력에서 입력 복원 불가능
  작은 입력 변화 → 완전히 다른 출력 (눈사태 효과)
- 용도: 비밀번호 저장, 무결성 검증, 디지털 서명
- 알고리즘: SHA-256, SHA-3, bcrypt, Argon2

## 5. HTTPS 암호화 체계 & 브라우저 역할
- 🔐 대칭키 암호화
하나의 키로 암호화/복호화
빠름, 실제 데이터 전송에 사용
예: AES-256

- 🔑 공개키 암호화 (비대칭)
공개키(암호화) + 개인키(복호화) 쌍
느림, 대칭키 교환에 사용
예: RSA, ECDH
📝 RSA
대표적 공개키 알고리즘
큰 소수의 곱셈 기반
키 교환 및 디지털 서명에 활용
- ✍️ 디지털 서명
개인키로 서명 → 공개키로 검증
목적: 무결성 + 부인 방지 + 신원 확인
- 📜 서버 인증서 (SSL/TLS 인증서)
서버의 공개키 + 도메인 정보 + CA 서명 포함
CA(인증기관)가 서버 신원 보증
- 🌐 브라우저가 수행하는 것
1. [연결 시작] 서버에 TLS 핸드셰이크 요청
2. [인증서 수신] 서버로부터 인증서 받음
3. [인증서 검증]
   - 유효기간 확인
   - 도메인 일치 여부
   - CA 서명 검증 (내장된 루트 CA로)
   - 인증서 체인 검증
   - 폐기 여부 확인 (CRL/OCSP)
4. [키 교환] 서버 공개키로 대칭키 재료 암호화 전송
5. [세션키 생성] 양측이 동일한 대칭키 도출
6. [암호화 통신] 대칭키로 실제 데이터 암복호화
7. [UI 표시] 🔒 자물쇠 아이콘, 인증서 정보 제공
- 📊 전체 흐름 요약
[브라우저] ←→ [서버]

1. ClientHello (지원 암호화 목록)
2. ServerHello + 인증서
3. 브라우저: 인증서 검증 ✅
4. 브라우저: Pre-master secret 생성 → 서버 공개키로 암호화
5. 양측: Session key 도출
6. 이후 모든 통신은 대칭키로 암호화

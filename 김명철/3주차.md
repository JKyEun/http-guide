# HTTP 게이트웨이와 캐시 정리

---

## 게이트웨이

### 게이트웨이란
서로 다른 프로토콜이나 네트워크 사이에서 번역기 역할을 하는 서버.

### 터널링
HTTP CONNECT 메서드로 두 끝점 사이에 투명한 파이프를 만드는 것. 게이트웨이가 데이터를 해석하지 않고 그냥 바이트를 양쪽으로 전달만 한다. 대표적 예시는 HTTPS 프록시.

**"해석하지 않는다"의 의미:**
- 일반 프록시: HTTP 메시지를 파싱하고, 헤더를 읽고, 캐시 확인하고, 수정함
- 터널: 암호화된 바이트 덩어리를 그냥 왼쪽↔오른쪽으로 복사만 함

터널에서 브라우저와 서버가 직접 TLS 핸드셰이크를 하고, 암호화 키는 둘만 안다. 프록시는 "누가 어디로 연결하는지"만 알고 내용은 모른다.

### 릴레이
단순한 형태의 프록시. HTTP를 완전히 이해하지 못하고 맹목적으로 바이트를 전달. hop-by-hop 헤더를 제대로 처리 못해서 버그가 생길 수 있다.

### MSA와 API 게이트웨이
마이크로서비스 아키텍처에서 정문 역할. 라우팅, 인증/인가, 로드 밸런싱, 속도 제한, 응답 집계 등을 담당. Kong, AWS API Gateway, Spring Cloud Gateway 등이 있다.

### CGI 게이트웨이
웹 서버가 외부 프로그램을 실행해서 동적 콘텐츠를 만드는 표준.

**구조:**
```
브라우저 → 웹서버(Apache) → CGI 프로그램 실행 → 결과를 HTTP 응답으로
```

**작동 방식:**
1. 요청이 `/cgi-bin/` 경로로 들어옴
2. 웹서버가 새 프로세스 생성
3. 환경변수로 요청 정보 전달 (QUERY_STRING, REQUEST_METHOD 등)
4. 프로그램의 stdout 출력을 HTTP 응답으로 사용
5. 프로세스 종료

**"게이트웨이"인 이유:** HTTP 세계와 프로그래밍 세계 사이를 번역해주기 때문.

**문제점:** 요청마다 프로세스 생성/종료 비용 발생 → 느림.

**발전:** FastCGI, mod_php, WSGI, Servlet 등으로 진화.

### CGI vs Node.js

| | CGI | Node.js |
|---|---|---|
| 구조 | 웹서버 + 외부 프로그램 | 웹서버와 앱이 하나 |
| 프로세스 | 요청마다 생성/종료 | 항상 실행 중 |
| 성능 | 느림 | 빠름 |

Node.js의 라우트 핸들러는 CGI가 아니다. CGI는 특정 역사적 기술을 가리키는 용어.

### CGI와 AWS Lambda 비교

**유사점:**
- 둘 다 "요청 올 때 실행, 끝나면 정리"라는 철학
- 상주 프로세스 없음, 상태 유지 안 함

**차이점:**
- Lambda는 컨테이너를 잠시 재사용 (Warm Start)하여 CGI보다 효율적
- Lambda는 AWS가 인프라 전체를 관리

Lambda는 CGI 철학의 현대적 부활. "상주 서버 없이, 요청 올 때만 실행"이라는 핵심 아이디어가 같다.

## 캐시

### 강력 새로고침
일반 새로고침(F5)은 조건부 요청을 보냄. 강력 새로고침(Ctrl+F5)은 `Cache-Control: no-cache` 헤더를 붙여서 캐시 무시하고 원본 서버에서 완전히 새로 받아옴.

### no-cache vs must-revalidate

| 헤더 | 의미 |
|------|------|
| no-cache | 캐시 저장은 되지만, 사용 전 매번 서버에 확인 |
| must-revalidate | 신선할 때는 그냥 쓰고, 만료 후에만 서버에 확인 |

핵심 차이: no-cache는 항상 검증, must-revalidate는 만료 후에만 검증.

### If-Modified-Since 작동 방식

1. 최초 요청 시 서버가 `Last-Modified` 헤더로 수정 시간 알려줌
2. 브라우저가 이 값을 디스크 캐시에 저장
3. 재요청 시 `If-Modified-Since` 헤더에 저장된 값을 붙임
4. 서버가 비교해서 수정됐으면 200 + 새 데이터, 안 됐으면 304

**저장 위치:** 브라우저의 디스크 캐시. URL별로 응답 헤더, 메타데이터, 본문을 함께 저장.

### If-None-Match가 여러 개일 때
```
If-None-Match: "abc123", "def456", "ghi789"
```
서버의 현재 ETag가 이 중 하나라도 일치하면 304 반환. 클라이언트가 여러 버전을 캐시하고 있을 때 유용.

### 인터넷을 나가지 않는 공용 프록시
인트라넷 프록시 또는 사설 프록시. 회사/학교 내부 네트워크에서만 동작하고, 같은 조직 내 사용자들끼리 캐시 공유. 내부 사이트 캐싱, 접근 제어, 대역폭 절약 목적.

### 토폴로지
네트워크 구성 요소들이 연결된 구조나 형태. 캐시 맥락에서는 "프록시와 캐시가 어떻게 배치되어 있는가"를 의미. 계층형, 메시형, 형제 캐시 등이 있다.

### 304 응답
검증(validation) 응답. "네가 가진 버전 그대로 써"라는 의미. 원서버뿐 아니라 중간 프록시 캐시도 304를 보낼 수 있다.

### 이더넷
LAN을 위한 물리/데이터 링크 계층 기술.

**OSI 7계층에서 위치:**
```
응용 계층 - HTTP
전송 계층 - TCP
네트워크 계층 - IP
데이터링크 계층 - 이더넷
물리 계층 - 이더넷
```

**하는 일:**
- 같은 네트워크 안에서 MAC 주소로 장비 식별
- 프레임 단위로 데이터 전송

**IP vs MAC:**
- IP 주소: 최종 목적지 (집 주소)
- MAC 주소: 바로 다음 장비 (주민등록번호)
